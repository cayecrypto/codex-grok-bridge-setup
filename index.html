What this preview verifies

The setup and an authenticated task/status path have been tested. Frequent polling and larger file/image transfers hit the current Reason transport limit. A separate encrypted transfer path is being built; do not rely on this preview for normal file delivery yet.

Model tasks require permission on your host and check the existing account route and quota. No API-key or paid-provider fallback is used. Grok Bot needs a local shell tool; this is not a native MCP plugin.

Keep the host running

The setup link distributes public installation files only. Your host's controls, pairing codes, task history and account credentials remain private. Network reachability still depends on both devices and their firewalls; the wizard reports Ready only after an actual matching response.

The launcher uses a script policy scoped to its own setup process. It does not change the machine's policy, install a service or start at login.

Repair reply delivery; keep your pairing

Version 1.0.3 fixes reply selection when older messages are still held. The helper approves only the unique paired-host reply matching the current request; older and unrelated messages remain untouched. If a reply failed after submission, check that same task ID instead of submitting the task again.

Choose the model and effort

Grokbot can discover your host catalog explicitly with -Capabilities, then choose supported -Model and -Effort values when submitting a task. Omitted options use host defaults. Discovery is separate; it is not added to every task.

The host validates selections against its actual catalog and account admission. Task receipts distinguish requestedModel/requestedEffort from effectiveModel/effectiveEffort. Unsupported choices fail without a paid-provider fallback.

Run the updated wizard to replace helper scripts while reusing your existing pairing. No re-enrollment is required. This update keeps the existing Reason transport and its file/request limitations; it does not switch to the optional Tailscale preview.

Long jobs and partial output

The host now defaults to no automatic task time limit; existing 1.0.3 clients receive that host change without reinstalling. Version 1.0.4 adds optional -TimeoutSeconds when submitting: 0 means unlimited, and 1 through 604800 selects a deadline. Omitting it uses the host default.

Check status sparingly, no faster than once every 90 seconds. After cancellation or a selected timeout, report the actual terminal receipt and fetch only its listed surviving artifacts. Partial output is not task success. Never resubmit a prompt automatically after a failed reply or deadline.

Explicit project writing

Version 1.0.5 adds -Workspace eyegym -Mode workspace-write for owner-authorized Eye Gym edits. The helper stays read-only by default, and writing requires the explicit named workspace. Host capabilities list the available workspace and whether writes are allowed; the host validates every request against its fixed owner mapping.

Work is saved in the isolated host checkout. Task receipts report workspaceId, mode and the actual workspaceChanges summary. Saving host changes and downloading listed artifacts to your laptop are separate actions. No automatic Git commit, push, connector installation or arbitrary repository access is added.

Run the wizard to upgrade your helper while retaining its existing pairing. The package contains no project source, host workspace path or account authentication.

Multiple bots, separate job results

Version 1.0.6 coordinates helper calls sharing one laptop and enforces a shared conservative budget of 10 requests per 600 seconds. A local transport_wait with requestSent: false is not a host queue acknowledgement. It returns the original task ID and a retry delay without sending that packet.

The host runs a bounded number of workers and queues additional tasks. Project jobs receive isolated worktrees: finished edits are not automatically combined into Eye Gym. Use the private owner dashboard to review a result and explicitly integrate it; stale reviews or conflicting changes fail without automatic merging, commits or pushes.

Account quotas, host resources and the existing Reason file/message limits still apply. This is not unlimited model throughput. Existing pairing is retained.

Reference images and compact delivery

Version 1.0.7 adds optional -ReferenceImage with -Prompt -GenerateImage and an explicit task ID. A separate lossy JPEG preview of at most 48 KiB is uploaded and verified before generation; your original file remains unchanged. Generated image delivery is also a labeled compressed preview, with the original retained privately on the host. Report actual receipt dimensions and hashes.

Reference uploads and artifact downloads can resume after a definite unsent transport_wait by explicitly repeating the same unchanged operation and task ID after its retry delay. Uncertain sends stop for inspection; never automatically regenerate. Pairing is retained and the shared Reason message budget still applies.
